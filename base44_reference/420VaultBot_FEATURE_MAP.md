# v3.11 feature map

## Access model
Canonical access is `app/services/access.py::check_access`.
- TOS is required when the TOS gate is enabled.
- Discord Administrator / configured admin / Vault Overseer bypass paid licensing after TOS for normal access.
- Beta Tester bypasses paid licensing only; TOS still applies.
- Ordinary users require an active entitlement and an activated active license.
- Subscribed state is derived from an active subscription (including valid past-due grace).

## Licensing
- Codes are generated by the backend (`app/core/licensing.py`) and signed with HMAC-SHA256.
- New admin website grants call the same subscription/licensing service used by the bot.
- Generated licenses are assigned to a Discord user and the bot attempts to DM an Activate License button.
- The persistent Discord license-channel activation panel remains available.

## Subscriptions/payments
- Plans live in `subscription_plans`; defaults are Monthly $25, Half Year $50, Yearly $100, Lifetime $150.
- Subscriptions track `billing_period_end`, `expires_at`, `grace_until`, provider IDs, and license code.
- Stripe/PayPal webhooks are signature-verified in `app/services/webhooks.py`.
- Manual approvals use transactional/idempotent service logic.
- v3.11 API exposes read-only subscription/transaction views but does not yet expose checkout creation.

## TOS and roles
Roles include Verified, Unverified, Subscribed, Beta Tester, and Vault Overseer. TOS acceptance is versioned and stored per guild/user.

## Tickets
Ticket types: crash, bug, vault, feature, request, payment, other. Website ticket creation creates the same private Discord support channel through `create_support_ticket()`.

## Server bootstrap
The bot creates/reuses configured default channels and stores the actual IDs for license, logs, and tickets. License/ticket panels are persistent and reused.

## Vault
The physical Vault has guild-scoped file/folder tables plus FTS5. The v3.11 API currently exposes Vault configuration/status/stats, not web file delivery.
