# 420VaultBot v6.4.0 — continuity and update-safety release

**This is a focused, working upgrade, not the full proposed feature roadmap.**

## Implemented
- Keeps the existing v6.3.6 Discord Command Center, full 420_help paginated button directory, native account/2FA experience, public profile view, admin GUI, welcome DM, physical Vault and Drive modules, and licensing/payment code.
- Release version harmonized in VERSION and app/version.py.
- Conservative updater now blocks downgrades, rejects missing critical release modules, runs in `--dry-run`, preserves installed user state, backs up overwritten source files, and attempts rollback on interrupted copy failures.
- Offline preflight tests for required modules, help buttons, 2FA, user profiles, welcome message and upgrade preservation/downgrade protection.

## Not included yet
Audio-key/BPM analysis, audio similarity engine, collection management, new social collaboration, new web download API and full remote server monitoring are roadmap items, not v6.4.0 features.

## Installation
1. **Back up your entire live installation separately** including .env, databases, accounts and license secrets. Stop the bot process.
2. Extract the release to a DIFFERENT folder from the live installation.
3. Run `upgrade_existing.bat` and enter the existing bot directory. Review version and confirm `UPDATE`. It does not copy user data.
4. Restart the original process or update the hosting deployment correctly. Run `420_version`, `420_help`, `420_admin`, and verify your login/2FA/profile interfaces.
5. Source backups live at `<installation>/backups/source_pre_v640_*`.

**Important:** This only upgrades the directory selected. If the hosting panel starts a different source folder, it will still run that older code. Static testing is not a live Discord integration test.
