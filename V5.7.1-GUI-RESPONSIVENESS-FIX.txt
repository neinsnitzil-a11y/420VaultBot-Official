420VaultBot v5.7.1 - GUI / Heartbeat Responsiveness Fix

What changed
- Removed the process-wide SQLite RLock from Database.connect(). That lock could be acquired directly on Discord's asyncio event-loop thread and block gateway heartbeats for 20-30+ seconds.
- SQLite remains in WAL mode and uses per-connection busy handling. Short helper operations retry transient SQLITE_BUSY/database-is-locked failures with bounded backoff.
- audit_log_worker database reads now run in worker threads instead of on the Discord loop.
- entitlement-worker expiration/reconciliation database scans now run in worker threads.
- Admin section navigation acknowledges the Discord interaction before rebuilding DB-backed embeds.
- Admin Refresh acknowledges immediately and rebuilds off-loop.
- Admin panels now use timeout=None plus stable custom IDs and are registered after startup, so panels created by this version can survive reconnect/restart.
- Vault scans continue in a background thread. With the global Python lock removed, their small SQLite commits no longer monopolize every other DB reader.

Important upgrade note
Panels created BEFORE v5.7.1 used Discord-generated component IDs and cannot be retroactively converted into persistent panels. Run 420_admin once after upgrading to create a new persistent admin panel. Newly created v5.7.1 panels are reusable.

Keep your existing .env and data/420vault.db when upgrading. The distributable intentionally does not contain live secrets or a live database.
